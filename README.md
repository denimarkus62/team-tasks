# Задачи команды

Общий дашборд задач: тематики, у каждой тематики свой исполнитель, внутри задачи со статусами, сроками и комментариями.
Страница: https://denimarkus62.github.io/team-tasks/

## Как это устроено

- Сайт статический (GitHub Pages), без сервера и базы.
- Все данные лежат в одном файле `data/tasks.json`. Каждое изменение на странице - это коммит в этот файл, поэтому вся история правок хранится в GitHub.
- Без ключа страница открывается в режиме просмотра.
- С ключом доступа можно добавлять и менять задачи.

## Файлы в задачах

К задаче можно прикрепить любой файл (до 20 МБ), в том числе сразу при создании. Файл кладется в репозиторий в папку `files/` под служебным именем `<id>.bin`, настоящее имя хранится в `data/tasks.json`. Расширение `.bin` нужно намеренно: GitHub Pages отдает такой файл как поток байтов и никогда не исполняет, даже если прикрепили html или js. Скачивается файл под своим именем.

Прикреплять и удалять файлы может тот, кто может править задачу (Роман, исполнитель, автор). Удалять чужой файл может только Роман. При удалении задачи или файла он стирается из репозитория, но остается в истории коммитов.

Сразу после загрузки файл по обычной ссылке (без ключа) может не открываться 1-2 минуты, пока GitHub Pages пересоберется. Тот, у кого есть ключ, скачивает файл сразу. Страница принимает только пути вида `files/<латиница и цифры>.bin`, остальное считает ошибкой.

Файлы публичные так же, как и вся страница. Договоры, реквизиты, пароли не прикреплять, для них давать ссылку на закрытую папку Яндекс.Диска в описании.

## Права

| Кто | Что может |
|---|---|
| Роман | все: тематики, исполнители, создание, правка и удаление любых задач |
| Иван, Алексей | создавать задачи (исполнитель подставится из тематики), менять статус и поля своих задач, писать комментарии |

Это защита от случайных ошибок, а не от злого умысла: ключ один на всех, поэтому технически он дает запись во все данные.

## Ключ доступа (выдает Роман)

1. GitHub, Settings, Developer settings, Personal access tokens, Fine-grained tokens, Generate new token.
2. Repository access: Only select repositories, выбрать только `team-tasks`.
3. Permissions, Repository permissions, Contents: Read and write. Больше ничего не включать.
4. Срок: до года. Когда ключ истечет, страница покажет красное сообщение, и нужно выдать новый.
5. Передать ключ Ивану и Алексею лично (мессенджер). В репозиторий и в задачи ключ не вставлять.
6. Сотрудник открывает страницу, выбирает свое имя, жмет «Ввести ключ» и вставляет его. Ключ хранится только в браузере этого человека.

## Добавить сотрудника

Открыть `data/tasks.json` на GitHub и дописать человека в `users`:

```json
{ "id": "sergey", "name": "Сергей" }
```

`id` - латиница без пробелов. Роль администратора задается полем `"admin": true`.

## Если что-то сломали

Каждое изменение - отдельный коммит с подписью, кто его сделал. История файла: вкладка History у `data/tasks.json`. Любую версию можно вернуть.

## Что учесть

- Репозиторий публичный (иначе бесплатный GitHub Pages не работает). От поисковиков страница закрыта (`robots.txt` и `noindex`), но по прямой ссылке данные доступны любому, кто ее знает. Пароли, цены и другие секреты в задачи не писать.
- Ключ хранится в браузере на домене denimarkus62.github.io, а он общий для всех страниц Романа на GitHub Pages (форум, база знаний, дашборд индексации). Поэтому на эти страницы нельзя ставить сторонние скрипты. Ключ дает запись только в этот репозиторий.
- Проверка прав ключа при вводе неточная: если у ключа нет права записи, об этом станет известно при первом сохранении.
- Изменения другого человека видны в течение минуты или после обновления страницы.
